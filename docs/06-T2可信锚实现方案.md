## 1. 背景：T2 要补的是哪一格

T1（独立进程锚）已抵抗 A2 的 C1/C2/C4，但有一个结构性缺口（`docs/02-系统架构.md:329`）：

- 单调序号 `seq` 与链头 `head` 活在锚进程内存里，**重启归零**；
- 密钥只能选 `ephemeral`（进程内存）或 `file`（落盘则被 A2-C1 读走）；
- 因此 A2 可以**重放一份旧检查点**——跨会话回滚无法检测。`scripts/tamper_demo.py` 结尾已如实写明这一缺口。

T2 的技术理由：只有 TEE 的安全存储能**同时**给出"A2 读不到"与"跨重启持久"。

术语速查：OP-TEE = ARM TrustZone 安全世界的开源 OS；TA = 跑在 OP-TEE 内的小程序（C 写）；QEMU = 软件模拟 ARM 开发板；RPMB = eMMC 上带只增计数器的防回滚分区。

### D1 的边界（什么不做）

- **不把 L1–L5 策略引擎搬进 TA**。TA 只能跑 C、内存受限，重写引擎工作量爆炸且超出证明点需要。
- 代价要诚实写进论文：策略判定的**过程**在安全世界之外（普通进程）。但策略文件完整性由 `policy_hash` attest 保证，A2 改策略会被发现——威胁模型层面无洞。
- 这条分工恰好符合 P4（最小 TCB）：TEE 里只有"盖章 + 数序号"。

## 3. 总体架构：壳不变，换心脏

T1 的进程壳（Broker ⇄ JSONL stdio ⇄ 锚进程）完全保留，只替换锚进程内部的链权威实现：

```
Broker (Python, 不动)
   │ JSONL stdio（与 T1 完全一致）
   ▼
锚进程 anchor --serve（Python：L1–L5 判定、会话状态、溯源存储照旧在此运行）
   │ 新增：seal / chain_append / chain_checkpoint / export_key 转发给 C 桥
   ▼
tg_bridge（新，C，长驻：stdin 读 JSON → 调 TA → stdout 回 JSON）
   │ libteec
   ▼
TA trustgate_ta（新，C：密钥 + seq + head，RPMB 安全存储）
```

关键设计点：

1. **链权威整体进 TA**。`chain_append` 在 TA 内原子完成：读 {seq, head} → 算 hash → HMAC → seq+1 写回 RPMB。序号与链头的权威（`docs/02-系统架构.md:350` 的原则）在 T2 下真正做到了"A2 触不到"。
2. **软模拟模式仅用于开发**。tg_bridge 提供一个不链接 libteec 的 soft 模式（文件模拟 TA 语义），让开发、单元测试不依赖 QEMU。**实验数据必须来自真 QEMU；soft 模式不允许出现在任何实验产物中**，此界限写进代码注释与论文。
3. **export_key 语义不变**。校验方仍在会话期间经可信通道取走密钥一次（与 T1-ephemeral 同模型）；差别在于 T2 的密钥跨重启持久且 A2 无从读盘。
4. **fail-closed 全程保留**：桥进程或 TA 会话挂掉 → 锚进程拒绝服务，调用方拒绝操作（沿用 `trustgate/anchor.py` `_rpc` 的现有语义）。

## 5. 实验设计

### E1 重放检测（`scripts/replay_demo.py`）

1. 会话 1 正常跑完，签发离机检查点 C1 = {seq=7, head=H7, mac}；
2. 锚重启；A2 把旧日志副本 + C1 塞回（假装什么都没发生）；
3. 会话 2 继续跑（TA 内 seq 已推进到 10）；
4. 校验：拿 C1 去问 TA——mac 合法但 seq(7) < TA 当前 seq(10)，** stale 检查点当场暴露**。

| 档位 | 预期结果 | 解释 |
| --- | --- | --- |
| T1 | 检测不到（构造上不可能） | 重启后密钥与序号归零，跨会话链连续性根本建立不起来——这正是差值本身 |
| T2 | 检测到 | TA 持久单调序号与重放检查点矛盾 |

### E2 延迟对比（T0/T1/T2）

复用 `eval/run_eval.py` 的组配置机制（C5 已支持按组选锚），新增 T2 组跑同一批良性任务，按 `latency_ms` 汇总三档对比表。这张表回答"上 TEE 要付多少性能代价"，与 E1 合起来构成 T1→T2 差值的完整量化。

## 7. 风险与诚实边界

1. **QEMU ≠ 真机**： limitation 照写，不夸大。
2. **soft 模式不进实验**：只用于开发与单元测试。
3. **判定过程在 TEE 外**：A2 可观测（A2-C4 本来就成立）但不可篡改；策略完整性由 attest 兜底。
4. **D6 的 accepted risk**：环境卡死无撤退线。缓解 = 代码先行（第 1 天即可对 soft 模式开发），环境步骤全部写成可复制命令清单，镜像源备选。

实现过程中对齐了两处既有偏差，如实记录：

1. **`chain_record` 公式对齐文档**（`trustgate/audit.py`）。文档 §5.3 的公式
   一直是 `sha256(prev_hash || seq || canonical_payload)`，代码却实现为
   `sha256(prev_hash || canonical({"seq": seq, **payload}))`。现已改为文档公式：
   seq 以十进制明文参与拼接，TA 因此无需解析 JSON 即可重算同一摘要。
   日志格式（记录字段）不变，旧日志用新代码无法通过校验——`logs/` 是
   实验产物可重新生成，无追溯需求。
2. **修复两个既有脚本的密钥导出断裂**。`scripts/tamper_demo.py` 与
   `scripts/run_task.py` 在 export_key 加固（Broker 默认拒绝经通道导出）
   之后没有传 `allow_key_export=True`，导致校验密钥为空串、MAC 全部
   "不匹配"——tamper_demo 的汇总页曾显示"完好日志 → 检测到篡改"。
   已修复并复验五行结果全部正确。

**预存在、与 T2 无关的发现**：Linux 上 `python -m unittest discover` 全量跑
时 `test_defense` / `test_forensics` / `test_model_eval` 之间共用 8799/8811
端口，`serve_corpus` 刻意 `allow_reuse_address=False`（Windows 判定预言机
完整性设计），先跑模块的服务器连接留下 TIME_WAIT，后跑模块 bind 失败。
基线（未改动的 master）同样复现。单模块跑全绿。修法（给测试服务器在
Linux 侧开 SO_REUSEADDR，或模块间错开端口）留给后续决策，不在本次范围。
